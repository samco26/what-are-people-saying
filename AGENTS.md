# Project instructions

- Read PROJECT.md before making changes. Stay within the current milestone.
- Assume no computer-science background; explain important decisions in plain language.
- Use Next.js, TypeScript and Tailwind CSS for the application.
- Refine the visual mockup with the user before implementing the application UI.
- Never expose API keys in browser code or public environment variables.
- Never commit `.env` files, credentials, tokens or authentication/session data.
- Keep source connectors separate and convert their results to a shared format.
- Handle unavailable sources and insufficient evidence explicitly.
- Never fabricate evidence, source URLs or themes. Label simulated data clearly.
- Do not permanently store social-media content.
- Do not add dependencies without a concrete reason.
- Do not add features outside the current milestone or the version-one scope.
- For application changes, run relevant tests and the production build before calling the checkpoint complete. Report checks that cannot run. Documentation-only changes do not require an application build.
- Commit each verified working milestone. Keep the GitHub repository private unless the user requests otherwise.
- Keep README.md accurate about setup, implemented functionality and known limitations.
- Keep PHASES.md current at each relevant checkpoint, using PROJECT.md milestone numbers and verified evidence. Distinguish code that passes local checks from a live integration that has actually succeeded.
