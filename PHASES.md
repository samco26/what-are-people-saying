## Latest verification

BETA 0.12.0 adds the category cards the user refined through the "Category Cards" mockup on 12 September 2026. The search plan (`src/lib/searchPlan.ts`) gains four fields: `category` (film, product, place, app or general), a short `kind` line, an `ambiguous` flag and a `suggestion`; the route copies them onto the result, and an ambiguous name is always answered with the general card plus the suggestion, never a guessed category. `src/lib/stars.ts` turns a sentiment split into a star rating: the positive share of opinionated posts, mapped through anchors pinned to the Rotten Tomatoes thresholds (60% is 3.5 stars, 75% is 4), pulled toward 3 when neutral posts are most of the sample or the sample is small. `src/components/CategoryCard.tsx` draws the four desktop layouts and one shared phone column; `PlatformStack.tsx` puts each platform's own rating beside its logo; recurring opinions now carry their support count (`support` on `RecurringOpinion`, which the analysis already computed and previously dropped). Two samples are labelled with a category (the Keychron K2 as a product, living in Melbourne as a place, the newest ChatGPT model as an app) so the sample mode shows the cards; there is no film sample. This machine has no Node.js, so `npm test`, `npm run typecheck` and `npm run build` could not run; the no-Node harness parsed all 34 source files and mounted the app, and the three sample cards were checked at 1280 by 800 (no card scroll, General view returns to the usual answer) and at 390 by 740 (card fills the screen, only the opinions box scrolls, no General view button). New tests cover the plan fields and the star anchors, neutral handling, small-sample shrinkage and a worked example, but have not run. Outstanding: the Vercel build, and a controlled live search to see how the plan classifies real subjects, how often it flags ambiguity, and whether the kind line is accurate.

BETA 0.11.0 adds a search plan before collection and changes X's ordering. One small OpenAI call (`src/lib/searchPlan.ts`) turns the typed subject into the phrases, keywords, exclusions and YouTube words that discussion would actually contain; the platform queries are assembled in code with all operator characters stripped from the model's output, a short subject as typed is always kept among the X terms, and any failure falls back to searching the subject as typed. X is asked for `sort_order=relevancy` (same per-post price). The plan's one-sentence interpretation is passed to the analysis as "Taken to mean". Two smaller changes ride along: X's per-process daily budget now counts only posts actually returned (empty and failed searches give their 20-post reservation back; the enforceable ceiling is the monthly spend limit in X's developer console, which is a manual setting outside the code), and YouTube fills each video's 30 places with earlier selections first and then the most-liked of the top and recent comments, with no minimum. New tests cover planning, fallback, sanitising, length limits, planned X terms and the relevance order, the adaptive passes carrying the queries, the budget refunds and the liked-comment preference. The docs and badge for this version reached `origin/main` in commit `b4ae406` ahead of the code, because a concurrent session committed the working tree; the code followed in `f67cb04`. Vercel deployed `f67cb04` (the live bundle carries this version's changelog text) and a controlled production search for "the weather in Tuscany in August" returned a full result in 7.8 s: `Server-Timing` reported plan 1.4 s, collection 0.7 s and analysis 5.3 s; 70 YouTube comments from 10 videos, 6 X posts from the last 3 months for a plain-English subject that the old exact-phrase query would not have matched, Reddit not connected, four recurring opinions. The budget refund and liked-comment preference are in the same build but are not separately observable from outside. `npm test`, `npm run typecheck` and `npm run build` still have not run on a machine with Node.js. This machine has no Node.js, so `npm test`, `npm run typecheck` and `npm run build` could not run; the no-Node harness parsed all 30 source files and mounted the app, and the query-building cases from the tests were executed in the harness page with the expected results. Live effect on match rates, the extra plan latency (expected one to two seconds) and the Vercel build are the outstanding checks.
